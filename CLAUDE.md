# FlipUp: notes for Claude

Poker night on your phones: no-limit Texas Hold'em for play chips. A host opens a table and friends join on their own phones with a 5-letter code; bots fill empty seats. There's also a bots-only mode that runs entirely on one phone. Texas Hold'em has nine themed mini game variants beside it, each with its own look, and the campaign has two floor games: roulette and blackjack. Read `docs/RULES.md` before changing any poker rule.

## Commands

- `npm run dev`: app plus the Worker and Durable Object, all local (http://localhost:5173)
- `npm run typecheck`: `tsc -b` over app, worker and tooling projects
- `npm test`: Vitest unit tests for `src/game`
- `npm run e2e`: Playwright, phone-sized Chromium, trimmed to the launch path (`online`, `bots`, `party`, `premium`, `settings` specs; the others are in git history before Phase 2), starts its own dev server on 5174. In the cloud sandbox Chromium is at `/opt/pw-browsers` and `@playwright/test` is pinned to 1.56.1 to match it. `SHOTS_DIR=/some/dir` saves a screenshot of each screen. If Playwright can't find its browser (the installed one is a newer build), set `CHROMIUM_PATH=/opt/pw-browsers/chromium`.
- `npm run check`: typecheck + unit tests + build. Run it before committing.
- `npm run deploy`: build and `wrangler deploy` (needs `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` in the environment; never commit them).
- After editing `wrangler.jsonc`, run `npm run cf-typegen` and commit `worker-configuration.d.ts`.

## Native app (iPhone and iPad)

- **Branches (the owner's rule, 6 Nov 2026): `main` is the one source of truth.** Every session starts from the latest `main` (the `SessionStart` hook `.claude/hooks/sync-main.sh` moves an empty session branch onto it, and warns when a branch with its own work is behind: merge `origin/main` first, resolving in favour of main's design). Finished work goes back to `main` through a pull request the same day, so no session builds on another's stale copy.
- **Design: read the box at the top of `docs/DESIGN.md` before any UI change.** The owner keeps the TestFlight design with small changes: deep blue instead of purple, no grain (a moving blue light field on pages), fewer spinners. The game pictures are the original drawn scenes (the detailed icons were tried and dropped). The paper/red redesign in the rest of that file is parked. New design decisions go into it first; new screens are mocked up for the owner before they're built.
- `native/`: Expo (SDK 58) and Expo Router, a new client for the same Worker. It imports the engine as `@game/*` (`native/tsconfig.json`, `native/metro.config.js`) through `native/src/engine`; never copy `src/game` into it. Every name, id and link is in `native/appInfo.ts`, read by `native/app.config.ts`. Campaign and AI Legends never ship in it.
- Design system (Phase 3): one set of tokens in `src/design/tokens.ts` (palette for light and dark, party colours and play-tile gradients, the type ramp with Dynamic Type caps, spacing on a 4pt grid, radii, shadows, motion), shared by the web and the app; `tokens.test.ts` checks it against `global.css`, so change both together. The app's theme is `native/src/theme` (`useColors()`: Apple's system colours for the neutrals on iPhone, the token palette elsewhere; `gradient()` for CSS gradients that also work on the web build). Components in `native/src/components`: `ThemedText` (every piece of text, by type step and tone), `PressableScale` (press feedback: 97% and dimmed in 80ms, spring back mass 1/stiffness 450/damping 30, light haptic, dim only under Reduce Motion), `Button` (party, primary, secondary, destructive), `PlayTile`, `Section`/`Row` (`components/grouped-list.tsx`, the Games-app style the owner picked in November 2026: a bold rounded heading over one big panel, `PANEL_RADIUS` 26, see-through white over the dark pages and Apple's grouped grey in light (`usePanel()`, which the lobby's Players and House rules, the game list and stats also use); a row is a large glyph in one calm tint (pale blue on dark, brand blue on light; a crown or star stays gold, delete red), a bold title with its state as a second line (`detail`), and a chevron or a control; rows highlight rather than shrink), `Switch`, `SegmentedControl` and `Stepper` (SwiftUI through `@expo/ui` on iPhone in `.ios.tsx` files, React Native fallbacks for the web build), `GlassSurface` (Liquid Glass on iOS 26, system blur below) and `haptics.ts`. Never import `@expo/ui/swift-ui` outside an `.ios.tsx` file: it crashes the web build. The web build is a single-page app (`web.output: 'single'`), because a static pre-render fixes the colours to light mode. The design catalogue and the other development screens are parked (`parked/`).
- Icons and motion (Phase 4): every icon is an SF Symbol, through `Icon` (`native/src/components/icon.tsx`), named by its SF Symbols name; Apple licenses SF Symbols for Apple platforms only, so its table gives each one a Material Symbol lookalike for the web build, and a new icon must be added there. No emoji or hand-drawn glyphs as icons. Motion rules, haptics, Reduce Motion and the on-device speed checklist are in `docs/MOTION.md`, whose **"The 20 rules" bind every animation, new or changed** (ease-out entrances, exits 20% shorter at 200 against 250, 30ms staggers, press 0.97, popovers from 0.95 and never from 0, no bounce on everyday UI, never tween while a finger is down, rubber-band past bounds, icons crossfade with scale and blur, one object that opens into itself keeps its identity; use `popIn()`, `SETTLE`, `stagger()`, `rubber()` and `knobStretch()` from `native/src/motion/presets.ts`, and `Swap`/`SwapIcon` (`components/swap.tsx`) for anything that changes into something else (never a bare ternary or `&&` on an icon or a button label), never `ZoomIn`, `springify()` or a cubic-bezier with a y above 1; `native/tests/motion-rules.test.ts` fails when they're broken; on the web use `--ease-out`, `--dur-exit`, `--stagger`, `--pop-from`); presets in `native/src/motion` (`useReduceMotion()` follows the setting live through `AccessibilityInfo`; `enter()`/`exit()` for small elements; screens and sheets always use the native stack, which fades instead of sliding under Reduce Motion). ## Layout

- `src/game/`: the pure TypeScript poker engine, shared by the app and the server. No DOM or Node APIs here.
  - `cards.ts`, `evaluate.ts` (hand ranking), `equity.ts` (odds and the bots' hand strength)
  - `holdem.ts`: dealing, blinds, betting rounds, side pots, showdown
  - `reducer.ts`: `applyAction()`, the only way a table changes. Server and phone run the same code.
  - `bots.ts`, `selectors.ts`, `validate.ts` (`parseAction()` for anything from the network), `redact.ts`
  - Bots: 40 named bots (`botStyles.ts`), four each of ten hidden styles, plus 600 "regulars" (`botProfiles.ts`). `botPlay.ts` decides: preflop from GTO charts (`botCharts.json`, 2–6 players at 100/40/20bb; 7–9 handed fold into the 6-max chart) bent by style, push/fold when short, and an equity check against the raiser's range for big raises and all-ins; postflop it imagines the opponents' hands from their public story (`botRange.ts`: preflop line plus every postflop move, weighted by how well each hand fits, adjusted by `game.reads`), then weighs check/bet sizes/call/raise/fold by equity, fold equity and what it wins when called, blended with a slice of GTO's mix from `botPostflop.json`. Styles set how much a bot reads ranges (`sense`), its leaks, bet-size tells, tempo and when it shows cards. `botEval.ts` is a fast evaluator (matches `scoreHand`) so a decision stays within a couple of ms on the server. `botMind.ts` keeps each bot's tilt, confidence and grudges in `game.minds`. `botTalk.ts` holds their fixed comment lines (ids `b:...`, never accepted from phones). A bot that speaks before the outcome ("c'mon!", a shove) is in `game.sweating` and always reacts when the hand ends (`afterHand()` in `reducer.ts`, `owed` skips the cooldown and the dice). On the phone, `useReactions()` in `src/screens/table/Bubbles.tsx` shows bot lines one at a time, holds outcome reactions back half a second to a second, and drops "c'mon" lines when the next card lands or the pot goes. `redactForDevice()` strips styles, reads, minds and plans. Rebuild the data with `gto/scripts/export_bot_charts.py` and `gto/scripts/train_bots.py` (its `--parity` output is `botPlay.parity.json`, which the unit test checks the TypeScript buckets against). `botSim.ts` plays bot tables (and scripted players, including a constant bluffer, `bluffBot`) for tuning; the bots note how often a player bets (`betFreq`) and call lighter against a constant bettor, and punish players who fold too much (`EXPLOIT` in `botPlay.ts`; see `docs/BOTS.md`); `scripts/botLab.ts` runs the full lab and fun score (see `docs/BOTS.md`), with the bots from before the update in `scripts/legacy/` to compare against. ## Rules that matter

- Device ids are secrets: a device id proves a phone owns its seat, friend code and party place, so no phone ever sees another's. `redactForDevice()` and `redactBj(game, deviceId)` swap every other phone's `deviceId` (and `hostDeviceId`) for `publicId()` (`src/game/ids.ts`, a one-way hash that's the same at every table, starts with `u:`); comparing a player's `deviceId` with `hostDeviceId` still works. Never send a raw `Game` or `Blackjack` to a phone.
- Hidden information stays hidden. `redactForDevice()` strips the deck and every hole card that isn't yours or face up. Bots-only tables keep the deck on the phone but the screens still only get the redacted view.
- Win/tie odds show only during an all-in run-out, when every live hand is face up. Never while betting is still possible (product owner's call). Every game has them (`runoutOdds()` in `src/game/runoutOdds.ts`: Hold'em exact, the mini games played out by their own rules like the bots), except Imposter (`showsOdds()`); Ghost leaves the ghost out until it's turned over, then a hand that doesn't beat it shows 0%.
- Every timed thing goes through `game.wakeAt` and a `tick` action. `parseAction()` never accepts `tick` from a phone.
- Chips are never created or lost: the "keeps every chip accounted for" test plays bot hands and checks the total after every step. Keep it passing.
- When a poker rule is unclear, ask the product owner, then write the answer in `docs/RULES.md`.
- Every animation, new or changed, follows "The 20 rules" in `docs/MOTION.md` (the owner's instruction, 6 November 2026): ease-out entrances, exits 20% shorter, 30ms staggers, press to 0.97, popovers from 0.95 out of their trigger, no bounce on everyday UI, nothing tweened while a finger holds it, rubber-band past bounds, icons crossfaded with scale and blur, one object kept as one object. Use the shared presets and tokens, run `npm test` and `npm run test --prefix native` (the motion-rules test), and name the rules a change touches in its commit message.

## UI style

**iPhone app: see the box at the top of `docs/DESIGN.md`.** What follows describes the web app.

Apple-like, with a party streak (every menu: setup, lobby, party, profile, sheets and the finish page; the game screen once cards are dealt keeps its own sizes, see the end of `global.css`): it should feel like Apple made a poker app for a night with friends, so bolder and bigger. Loud gradients on what you tap to play, chunky buttons with a bottom edge (`--party-*` tokens in `global.css`), heavy (800) large titles and the main tap targets, bold (700) card headers, big tap targets, a bright capsule on the chosen tab and a hot-pink join button. The Party block at the end of `home.css` holds the Home version. The Party tab has one loud card (Host a party), then flat rows (Your party, Join a party, Add a friend), a flat friend code cell and a bold "Friends" heading. No ambient glow behind screens or cards: colour lives in the gradient on what you tap, with a soft shadow (`--shadow-soft`) under it. System font only (SF Pro on iPhone, the platform default elsewhere), regular weight for body text, semibold for headings and buttons, bold for large titles and for the headers of cards and buttons you tap (Play with Friends, the game cards, banners). Light mode is white with `#f2f2f7` cells, dark mode is true black with `#1c1c1e` cells, and the accent is system blue. Cells are flat (a soft fill, no outline, no shadow). Glass (the blurred, see-through look) stays on what floats: the tab bar, capsules, sheets and toasts. Large titles on Home, grouped rows with a coloured icon square and a chevron, a banner card with its own action bar for the one main next step. Instant feedback (press scale, haptics, confetti, card flips) that never blocks play. Profile pictures are emojis (pick from the grid or type any). Respect `prefers-reduced-motion`. Plain writing: no buzzwords, contractions are fine.

Never put decorative boxes on a button: no empty code slots, fake input fields or placeholder tiles on something you tap (the owner's rule). They read as a field you can type in. A button is its label, an icon, a line and a chevron; the real code boxes belong only on the screen where you type the code.

Every colour, size, radius and shadow is a token in `:root` in `src/styles/global.css`. Colours needed from code live in `src/ui/theme.ts`. Don't hard-code new values; spacing is on a 4px grid.
